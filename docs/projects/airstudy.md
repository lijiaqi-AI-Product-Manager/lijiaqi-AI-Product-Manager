# AirStudy

**用机场、路线与飞行记录组织专注时间的 Android 体验。** 面向希望把专注过程具象化的学习者与工作者，围绕准备、计时、暂停、到达及回顾形成交互。

## 技术与产品结构

本地工程采用 Kotlin、View/XML、Hilt、Room、DataStore 与 Gradle 多模块架构，包含 Ktor 服务端。模块涉及机场检索、飞行准备与选座、专注服务、环境音、完成与登机牌、记录、统计、账号及小组件。

实现重点是前台 Service 和界面之间的一致状态、进程恢复、后台任务、时间检查点、数据库迁移与账户切换。UI、交互、数据接口及相同输入输出分别保存证据，静态源码检查、实际构建、单元测试、原生截图和手机体验分别记录。

## 使用与开发路径

产品交互围绕：选择机场与路线 → 准备专注会话 → 计时与声音 → 完成 → 登机牌与记录。具体模式以已实现和已验证的链路为准。

本地开发从工程的开发入口与当前模块规格开始，配置 Android SDK 与 JDK 后，用 Gradle wrapper 构建、运行相关模块测试。当前公开仓库只有项目名称与许可证，**不提供完整 Android 源码、公开安装教程或可下载成品**；本页不把本地实现描述成公开代码交付。

## 迭代中处理的难题

- **计时与生命周期：** 准备阶段、真实服务、界面状态与后台重试需要指向同一请求和会话；只有得到匹配驱动的实际确认才进入起飞状态。
- **账号和迟到结果：** 账号切换、退出及旧任务清理需要限制归属，避免冷恢复时误退休当前 owner，或旧结果影响新账号。
- **起点与计划同步：** 起飞、取消、完成和落地起点更新需要跨页面与服务保持一致，不能让首页仍显示过期机场。
- **验证可移植性：** 校验路径统一指向当前仓库，补充证据缺失时记为跳过；缺证据不能记通过。历史白皮书的测试数字不替代本轮收据。
- **视觉与行为分开验收：** 原生图能证明当前页面绘制，不能自动证明和参考产品逐屏一致或手机已经验收；地图配置和未完成闭环独立保留范围。
