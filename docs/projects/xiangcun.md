# 湘村小灶数字化

**把扫码点单、后厨、会员与账本接成门店每天能用的流程。** 面向独立餐厅的顾客、老板及运营人员，也通过品牌配置支持复用到其他门店。

## 功能与技术

顾客端与老板端使用 React、TypeScript 和 Vite；Hono 与 better-sqlite3 提供单进程后端；Zod 契约在前后端共享。品牌名称、配色、菜单、字体和问答从店铺配置注入，图片与字体可自托管。

顾客扫桌码选菜、按辣度与备注管理购物车、下单、加菜、查看取餐进度与会员余额。老板端管理实时订单、接单和出餐、菜品状态与价格、会员储值、退款、对账、经营看板、历史订单、跨夜日结及交接班报表。SSE 推送新订单；打印模块适配小票与标签，包括本机 USB 路径。

## 上手路径

配置品牌与独立管理员密码，按锁文件安装依赖，分别运行后端、顾客端与老板端：

```bash
npm ci
npm run dev:server
npm run dev:customer
npm run dev:admin
```

顾客入口使用 `http://localhost:5173/?table=12` 这样的桌号链接；老板进入 `http://localhost:5174` 登录。先核对品牌菜单、支付记账方式与营业时区，再走完整点单、收单、出餐和对账流程。打印按设备操作指南配置纸张、编码与连接后实机检查。

## 迭代中解决的难题

- **加菜不能改掉历史账：** 原单保留下单时金额，加菜生成独立子单；接口统一展示父单取餐号，同时汇总整桌金额，退款与账本各自可追溯。
- **成功重试被误报失败：** 幂等检查先于“购物车为空”等业务校验，避免第一次成功清车后，重试反而显示下单失败。
- **跨夜营业日：** 日结以门店时区和营业班次计算；晚市尚未结束时统计到当前班次，不误查成昨晚，也不漏掉当前分钟的新单。
- **钱、认证与实时推送：** 账本只增不删，金额统一格式；SSE 使用短时一次性票据，避免管理员令牌进入 URL 与日志。
- **图片一次上传、两端一致：** 一次解码生成详情大图与列表缩略图，修改或删除同步生效，旧数据回退兼容，减少移动端无效下载。
- **打印走出浏览器：** 按两类设备处理纸宽、编码、切刀和 TSPL 标签模式，同时支持 Windows 本地 USB 出票。
- **全链路测试污染：** 用例独立准备会员、菜价、购物车和图片条件，按自己的订单断言，减少历史数据、跨零点与其他测试导致的误判。

## 范围与业务

电子钱包、现金等可作为柜台支付记账；系统储值在账内扣减，这不等于集成了在线收单网关。当前菜品数量不作为库存管理，会员等级、成长值与完整权益不能从视觉卡面推断为已上线。设备出票效果与生产部署仍需在具体门店环境验证。

本人负责从需求、AI Coding、信息架构到产品与运营的推进；套餐组合与经营分析来自实际业务实践。简历中的经营增长属于本人履历陈述，不用源码测试替代经营数据审计。
